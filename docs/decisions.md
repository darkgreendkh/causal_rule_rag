# 重要技术决策

本文只记录会持续影响项目的重要选择及原因，不记录普通代码实现。功能发生变化时，
应同步检查本文、`architecture.md` 和 `features.md`；没有新增重要决策时，不添加占位条目。

## D1：使用 Neo4j 同时保存图数据和向量

原因：

- 一期数据量小、单机单用户，使用一个数据库可以减少部署和数据同步成本。
- Neo4j 既能表达实体关系，也能为 Chunk 建立 cosine 向量索引。
- 图谱关系保留 `source_chunk_id`，可以统一完成检索、溯源和删除清理。

影响：当前不使用独立向量数据库；Neo4j 专有时间类型和不存储 `null` 属性的行为在
数据库边界统一适配。后续若引入独立向量库，需要重新处理双写和一致性。

## D2：使用本地 BGE-M3 Embedding

原因：

- 法规语料以中文为主，需要适合多语言语义检索的模型。
- 本地运行不需要把原文发送给 embedding 服务，也不依赖额外 API。
- 归一化向量可直接配合 cosine 相似度。

影响：Neo4j 向量索引维度固定为 1024；替换不同维度的模型时必须重建向量和索引。

## D3：优先按法规结构分块

原因：

- 标题、条款和表格比固定长度切分更能保留法规语义边界。
- 800 字符上限控制单个证据块长度，80 字符重叠减少长文本边界信息丢失。
- 表格按行切分并重复表头，避免字段含义与数据行分离。

影响：Chunk 大小按字符而非模型 token 计算；后续改变分块策略需要重新摄取文档。

## D4：一期使用 FastAPI BackgroundTasks

原因：

- 当前是单机、单用户且文档数量少，不需要引入 Redis 和 Celery。
- 上传可以立即返回 `202`，前端通过轮询展示处理状态。

影响：任务不持久化、不支持断点续传；服务重启会清理派生数据并把未完成任务标记为
`FAILED`。

## D5：图谱抽取使用受约束的 LLM JSON 输出

原因：

- 法律实体类型固定后更容易合并、查询和可视化。
- `temperature=0` 降低同一文本多次抽取的随机差异。
- Pydantic 校验和一次纠错重试可以处理常见格式错误，又避免无限重试。

影响：两次输出仍不合法时，整份文档处理失败并清理派生数据。

## D6：保留纯向量与图谱增强两种检索模式

原因：

- `vector` 是基础对照，可用于论文消融实验。
- `hybrid` 从向量 Top 5 的实体进行一跳扩展，可以观察图谱带来的额外证据。
- 固定为向量 5 个、图扩展最多 3 个、上下文最多 8 个，便于当前阶段稳定比较。

影响：上述 Top 5 / 扩展 3 的口径适用于上传资料库。研究资料库另提供同源三模式，见 D10；当前没有 reranker，新增排序算法应保留可独立运行的基础模式并更新实验边界。

## D7：回答必须可回溯到原始 Chunk

原因：

- 法律问答需要让用户检查结论依据，不能只返回生成文本。
- `[S1]` 引用、原始 Chunk、召回渠道和图谱路径共同提供证据链。
- 没有召回证据时直接拒答，避免大模型脱离知识库生成答案。

影响：任何新的检索或生成模块都必须继续返回可定位的来源 Chunk。

## D8：自动化测试显式注入配置

原因：

- 开发者通常会在根目录 `.env` 配置真实 LLM，测试结果不应随本机密钥状态变化。
- `create_app` 已支持配置注入，测试可直接声明所需状态，无需修改进程环境。

影响：依赖配置状态的测试必须显式传入 `Settings`，不能假定本地 `.env` 为空。

## D9：多轮问答采用浏览器本地会话与检索前问题改写

原因：

- 演示系统使用频率低，本地多会话历史已能满足回看需求，不需要引入新的数据库模型和
  管理接口。
- 直接使用“上述义务”等追问进行向量检索容易丢失主题，检索前改写能补全指代和省略。
- 历史与本轮证据分离，可以继续保证法律回答的每个结论可回溯到当前检索结果。

影响：浏览器可保存、切换、重命名和删除多个本地会话，每个会话最多保存 20 轮完整
结果，请求只携带当前会话最近三轮问答文本；有历史的问答会增加一次大模型改写调用。
会话数量不主动限制，达到浏览器存储上限时需要用户手动清理。更换浏览器、清理站点
数据或更换设备后无法恢复。

## D10：上传资料库与研究资料库分离，同源比较三种研究检索

已接受。上传文档继续使用原来的 Chunk/实体关系与删除语义；研究资料使用带规范版本的条款、事项和独立研究图。研究库内 vector、hybrid、causal 共享同一批解析来源与向量，避免用不同分块或不同来源混充方法对照；代价是维护两种明确的数据模型和选择入口。

## D11：表达式执行和语言生成分离

已接受。资格、材料、时限、动作顺序和状态效果由受限 DSL 与确定性重放计算，大模型只生成候选与解释。未知参数或审批结果保留 unknown，不能由生成文本补足；固定初始规则和模型候选使用不同审核来源。此边界降低自动抽取的覆盖速度，但使违规、资料不足和真实外部结果可区分。

## D12：初始核对与人工审核绑定来源和规则版本

已接受。初始规则包的静态条件只对 `source_review_manifest.json` 明列的 36 个文件 SHA-256 版本启用。来源变化后仍可定位的新原文不自动证明旧阈值正确，必须生成待重新核对候选并暂停相关能力；不能重新生成清单来绕过语义核对。人工审核也应绑定条件、时空范围与证据指纹，避免旧审核状态被静态规则 ID 带到新版本。

后果：正文、元数据乃至换行字节变化均可能使来源校验失配，需要明确复核。规则资料清单不代表现行政策目录；已知起效且未规定终止日的规范采用开放结束，但仍保留当前清理状态未核验的说明。

## D13：研究知识以版本快照重建，独立投影到 Neo4j

已接受。每个研究配置拥有独立 build_id 和版本头；JSON 快照保存可重放的全部数据，Neo4j 使用 ResearchNode/RESEARCH_LINK 投影，不混写上传实体图。审核、来源移除或来源变化使旧配置失效，保留磁盘旧快照作审计；这是以额外存储换取明确版本边界，而非原地覆盖规则与社区。

## D14：强依赖先收缩，社区与路径有界搜索

已接受。有效且时空兼容的强因果依赖先形成不可拆组，再执行 Leiden 社区划分与层级细分；有向路径限制候选数、跳数和证据量，流程修复限制状态数。由此可以控制演示系统开销，但候选路径不保证全图全局最优，截断修复不等于无解。RPC/SCS、路径权重与阈值是工程定义，正式科研验证前不称为调优结果。

## D15：研究文献与政策规则使用不同证据身份

已接受。8 篇 PDF 通过原文本层逐页保留，供未限定事项的研究基础检索使用；不将学术讨论直接转换为行政审批条件。当前宏观/微观图来自政策目录、条件及动作，跨层关系限于明确来源和身份对应；没有实现任意 PDF—政策或跨分块实体的自动语义融合。论文方法描述必须保留这一实现边界。

## D16：实验按金标准来源分层，自动层进入仓库并可重跑

已接受。实验分两层：金标准由语料结构或缺陷注入程序化确定的部分（E04—E07、E09—E11）实现为
`backend/experiments/`，离线复用 `.runtime/research/embeddings.json` 的向量缓存，不连 Neo4j、
不调用生成模型、不写入正式知识库，结果以 JSON 与汇总表写入 `docs/thesis/experiments/`；
需要独立人工标注的部分（E01—E03、E08）只冻结协议与样本量，不用自动层数据代替。

后果：检索评测使用的是规则原文引用构成的银标准，与双层图谱同源，其精确率优势不能作为独立
效果证据，必须同时报告召回、证据完整率与消融间的相对变化。自动层的取舍与排期见
`docs/experiment-plan.md`；原 `docs/参考/实验计划.docx` 只作为选题阶段记录保留。

## D17：下一步候选排除已完成动作

已接受。动作效果在本模型中是常量赋值，重复执行一个已完成动作不改变状态，也不对应办事含义，
因此 `next_steps` 不再把它列为候选。该缺陷由 E10 的任务级评测发现：修正前推荐列表首位始终是
刚完成的步骤，Top-1 命中率为 0.000，修正后为 0.9274，平均候选数由 3.08 降至 1.26。

后果：单元测试检查的是返回结构，不足以发现候选集合的语义缺陷；面向任务的自动评测需要与
单元测试并存。修复计划搜索仍允许枚举全部动作，其重复插入由状态去重与代价剪枝消除。

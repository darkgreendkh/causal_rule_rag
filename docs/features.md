# 功能与模块说明

本文记录当前代码已经具备的能力，不把计划中的功能写成已实现。功能发生变化时，应
同步更新本文、`architecture.md` 和 `decisions.md`。

## 文档管理

本节至多轮问答描述上传资料库；研究资料库的增强能力见后文。

- 上传单个 UTF-8 `.txt` 或 `.md` 文件。
- 拒绝空文件、错误扩展名、非 UTF-8 内容和 SHA-256 重复内容。
- 原文件保存到 `data/uploads/<document-id>.<ext>`。
- 后台处理并展示 `PENDING`、`PARSING`、`EMBEDDING`、
  `EXTRACTING_GRAPH`、`COMPLETED`、`FAILED` 状态和 Chunk 进度。
- 处理失败时保留原文件和错误信息，清理已经生成的 Chunk 与图关系。
- 服务重启时将未完成任务标记为失败，不进行断点续传。
- 删除文档时同步删除原文件、Chunk、来源关系和孤立实体。
- 文档创建时间从 Neo4j 读取后统一转换为 API 可序列化的时间类型。

## 文档分块

- 识别 Markdown 一至六级标题、法规“第 X 条”和普通段落。
- 默认每个 Chunk 最多 800 字符，长文本使用 80 字符重叠。
- Markdown 管道表格和 TXT 制表符表格保持为完整块。
- 超长表格按行拆分并重复表头。
- Chunk 保留序号、所属标题、条款号和原始文本。
- 没有标题或条款号的 Chunk 会稳定返回 `null`，不会导致列表读取失败。

## 向量索引

- 本地延迟加载 `BAAI/bge-m3`。
- 批量生成并归一化 1024 维 Chunk embedding。
- 使用 Neo4j cosine 向量索引保存和检索 Chunk。
- 向量查询只返回状态为 `COMPLETED` 的文档。

## 知识图谱构建

- 使用 OpenAI 兼容大模型从每个 Chunk 抽取固定 JSON 三元组。
- 抽取温度为 0；校验失败时携带错误信息重试一次。
- 实体类型限制为法律、条款、机构、角色、组织、法律概念、行为、权利、义务、
  处罚和其他 11 类。
- 规范化同类型实体名称并在 Neo4j 中合并。
- 保存 Chunk 对实体的 `MENTIONS` 以及实体间带来源 Chunk 的 `RELATES_TO`。

## Chunk 可视化

- 按文档顺序查看 Chunk。
- 展示 Chunk 序号、标题或条款号及完整原文。
- 表格以原始等宽文本展示。

## 知识图谱可视化

- 使用 Cytoscape.js 展示实体节点和关系边。
- 支持按已完成文档筛选和按实体名称、类型搜索。
- 支持缩放、拖拽和自动布局。
- 点击实体或关系可查看类型及来源 Chunk ID。
- 默认最多展示 300 个节点，超出时显示截断提示。

## RAG 问答

- `vector` 模式：语义向量召回前 5 个 Chunk。
- `hybrid` 模式：在向量结果基础上通过实体关系进行一跳扩展，最多增加 3 个 Chunk。
- 图谱扩展按连接路径数和种子相似度排序。
- 最终上下文按 Chunk 去重，最多包含 8 个 Chunk。
- 提示词要求只依据上下文回答，关键结论使用 `[S1]` 形式引用。
- 没有召回证据时明确返回知识库证据不足。
- 返回原始 Chunk、向量分数、`vector/graph` 渠道和图谱路径。

## API 与运行支持

- 提供文档上传、列表、Chunk、删除、图谱、问答和健康检查 API。
- 健康检查返回 Neo4j 连通性、embedding 模型名和 LLM 配置状态。
- Docker Compose 提供 Neo4j 5.26 Community 单节点环境。
- 后端包含分块、摄取、抽取、检索、API 单元测试及可选 Neo4j 集成测试。
- 健康检查测试使用显式测试配置，不受根目录 `.env` 是否配置 LLM 影响。
- 前端提供概览、侧栏导航和桌面优先的响应式工作台，并提供 ESLint、TypeScript 检查
  和 Vite 生产构建。

## 多轮法规问答

- 浏览器保存多个本地会话，可查看、切换、重命名和直接删除；每个会话最多展示 20 轮。
- 新建对话不会删除历史，未提问的空白会话不保存；刷新页面后可恢复当前会话和历史。
- 每次请求只携带当前会话最近三轮问题和回答，不在后端或 Neo4j 保存会话数据。
- 有历史时先使用大模型把当前追问改写为独立检索问题，再执行原有向量或混合检索。
- 历史只用于理解指代和省略，不作为法规证据；每轮回答仍必须引用该轮返回的来源。
- 每轮记录独立保存检索模式、原始 Chunk、召回渠道和图谱扩展路径。

## 当前不包含

- 上传资料库不接收 PDF、Word、OCR 和其他文件格式；研究资料库仅解析随项目提供的 8 篇 PDF 的已有文本层。
- 登录、多用户、多租户和权限控制。
- reranker、关键词检索和其他召回融合算法。
- 服务端会话持久化、跨浏览器同步和流式回答。
- 图谱人工编辑、任务断点续传和生产部署方案。

## 研究资料库：规则与来源

- 36 份政策、1481 个政策单元、115 事项；8 篇研究文献保留 357 页文本。数量和能力细分见 [数据覆盖](data-coverage.md)。
- 单文件多规范分别保存规范名称和版本，第一条不会跨规范冲突；引用保留路径、规范名、条号和原文。
- 每个单元有 mapped 或具体 excluded 状态；部分结构化不等于整条已完整编码。
- 初始规则包有 288 条规则与 233 动作；启用依据是实现阶段对固定来源版本的核对。来源 SHA-256 变化时旧固定规则降为候选并阻止直接启用。
- 模型抽取限制所选事项字段、动作和受限 JSON DSL，单条款最多 10 候选、单请求最多 5 条款。可解析但结构/引用错误的候选保留供查看；非 JSON 或超预算请求报告错误。
- 审核状态和来源删除引发版本重建。研究来源移除保留原文件；上传文档删除仍删除上传原文件，两者语义不同。

## 三种研究检索模式

三种模式在 `dataset=research` 下共享原文单元与向量预算。`vector` 直接取文本相似度前 8；`hybrid` 使用前 4 个种子，经宏观无向邻接的两条边扩展其他来源，补齐至 8；`causal` 使用社区、有向路径、规则条件及完整证据约束。基础两模式不执行流程校验。

上传资料库保留原有 `vector` Top 5 和 `hybrid` 最多补充 3 个 Chunk 的实现。比较三条研究方法时必须固定 `dataset=research`；不能将上传 Chunk 与研究条款/PDF 页混为同一对照语料。

## 流程操作与限制

- 字段区分申请事实、政策参数和外部事实。费用标准、退休边界、信用及资格认定没有资料时保留缺口。
- 三值核查输出首个错误、缺失字段、来源证据和模拟状态；规则满足不等于主管机关已作决定。
- 准备、提交、补正、确认、转移和支付等动作按真实引用建模。外部确认只能记录请求已经提供的结果。
- 最小修复仅调整拟执行动作，不改历史、不修改不可变事实、不创造审批结果；搜索达到预算会明确报告截断。
- 下一步返回尚未完成动作的状态和可用预览，由页面确认后加入本地模拟序列；已完成动作的效果是常量赋值，重复执行不推进状态，因此不进入候选。
- 来源日期未知、已知期限外或地域不匹配时返回 unknown；未明确终止日的规范保留开放结束，不宣称已经核验现行有效性。

## 研究边界

目前没有真实政务身份、材料、信用或审批系统接入；外部确认是输入事实。没有最终贷款额度计算、任意新事项自动建模、任意跨分块实体融合或 PDF 文献到审批规则的推断。九个消融配置可以分别构建，阈值为固定工程默认值；本阶段不执行正式科研实验，不报告优于基线的效果或统计显著性。
